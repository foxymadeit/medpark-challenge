# Liminal interaction audit

This matrix records the code and automated checks completed on `frontend-secure-mom`. “Verified” means the handler, route, state transition, error path, and relevant automated test were inspected. Hardware and backend rows state their remaining integration requirement explicitly.

| Page             | Control                               | Expected behavior                                                                         | Result                                                                        |
| ---------------- | ------------------------------------- | ----------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------- |
| Entry            | `/` and `/login`                      | Open the Meetings page; there is no sign-in                                               | Verified by UI and e2e tests                                                  |
| Top bar          | Settings (Administration / System)    | Opens a menu with Administration and System; Esc closes it and returns focus              | Verified by UI and e2e tests                                                  |
| Meetings         | Department card                       | Opens New Meeting with the chosen type                                                    | Verified by UI test                                                           |
| Meetings         | Templates / All meetings              | Resolves to `/templates` / `/history`                                                     | Route and render verified                                                     |
| Meetings         | Record / Upload mobile actions        | Opens department selection, then standard setup                                           | Handler and route inspected                                                   |
| Templates        | New / Edit                            | Opens editor                                                                              | Verified by UI/workflow tests                                                 |
| Templates        | Start                                 | Prefills setup without starting the microphone                                            | Verified by UI test                                                           |
| Template editor  | Participant/topic/reorder/save/cancel | Saves validated setup; cancel returns to templates                                        | Handlers inspected; save covered by workflow tests                            |
| New Meeting      | Record / Upload / Continue            | Creates one meeting once and routes to chosen input                                       | Verified by UI test; busy state prevents duplicates                           |
| Recording        | Start / Pause / Resume / Stop         | Controls MediaRecorder and persists local checkpoints                                     | Verified with mocked MediaRecorder; physical microphone pending deployment QA |
| Upload           | Choose/drop/remove/replace/write      | Validates WAV/MP3/M4A/FLAC and starts processing                                          | Verified by UI and validation tests                                           |

| Minutes          | Edit/save/cancel                      | Persists corrections and feedback; cancel discards draft                                  | Verified by UI/workflow tests                                                 |
| Minutes          | Task owner/deadline/source            | Uses stable staff ID; timestamp opens transcript                                          | Verified by UI/workflow tests                                                 |
| Minutes          | Participants                          | Selects existing active staff only and snapshots identity                                 | API and component inspected; immutable snapshot test passes                   |
| Minutes          | Mark review complete                  | Validates required data before enabling email preview                                     | Verified by UI/workflow tests                                                 |
| Email preview    | Back / edit body                      | Returns to review; edits local message draft                                              | Handler inspected                                                             |

| Voice enrollment | Record/retry/save/back                | Targets an existing staff profile and stores explicit enrollment                          | Workflow and recorder tests; recognition remains mocked                       |
| Admin            | People                                | Create/edit/deactivate official profiles                                                  | UI test (create); handlers inspected                                          |

| 404              | Back to meetings                      | Broken routes show 404 and return to meetings                                             | Final-state tests                                                             |

All destinations declared by `Link`, `NavLink`, and `navigate()` were compared with `src/router.tsx`. Legacy routes intentionally redirect to their canonical meeting route. No force navigation or external route is used.

The final local Vite server started successfully, but this execution environment exposed no browser surface to the computer-use tool. Visual click-through is therefore not claimed here; rendering, navigation, responsive rules, and interactions are covered by the automated suite and code audit. Physical microphone and local SMTP remain deployment-machine checks.
