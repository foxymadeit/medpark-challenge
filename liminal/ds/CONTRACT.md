# DS Contract: правила работы с дизайн-системой в этом проекте

**Источник ДС:** ds_scan (своя)
**Figma-файл:** https://www.figma.com/design/QYy8I55YDJRojTI6UCZENa/Liminal-%E2%80%94-Design-System
**Дата сканирования:** 2026-11-04

## Главное правило

Любая задача по интерфейсу идёт через эту ДС: компоненты из `ds/components.md`, токены из `ds/foundation.md`. Прибитые цвета, размеры, радиусы и шрифты в обход Variables запрещены.

## Что значит «через ДС»

1. **Компоненты только из каталога.** Инстансы по Node ID, похожие с нуля не рисуем.
2. **Цвета только через смысловые Variables** из коллекции Color.
3. **Типографика, радиусы, отступы через стили и Variables.**
4. **Auto Layout везде.** Шаблон экрана и правила кадров описаны в заметках проекта.

## Если нужного нет

- **Нет компонента:** добавить его в Figma на COMPONENTS или PATTERNS с описанием и вариантами, дописать строку в `ds/components.md`, потом использовать на экране.
- **Нет токена:** добавить Variable в смысловую коллекцию с привязкой к примитиву, дописать в `ds/foundation.md`, потом использовать.

## Синхронизация

Индекс должен совпадать с Figma. ДС поменялась: перезапустить `ds_scan`. Правки индекса руками помечать датой и причиной.

## Что запрещено

- Прибитые значения там, где есть Variable.
- Новый компонент прямо внутри экрана, если его можно собрать из существующих или вынести в ДС.

## Когда правила можно нарушить

Только по явной команде «здесь без ДС». Такой кадр помечается «ad-hoc, не часть продукта».
